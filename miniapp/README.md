# Scout Mini App

Тёмный интерфейс из предоставленного владельцем архива: графитовый фон,
сиреневые акценты и разделы «Обзор», «Заказы», «Каналы» с нижней навигацией.

## Режимы

Вне Telegram показывается явно помеченное демо с вымышленными данными.
Изменения остаются в памяти страницы до перезагрузки. Статический просмотр:

```bash
python3 -m http.server 8081 --bind 127.0.0.1 --directory miniapp
```

При открытии из меню бота клиент отправляет подписанные Telegram `initData`
в заголовке каждого API-запроса. `scout/web.py` проверяет HMAC, ID владельца,
время входа (до одного часа, допуск часов 30 секунд) и повторные поля.
Ошибка рабочего входа не заменяет реальные данные демоданными.

## Рабочий кабинет

- Проверенные заказы из SQLite без минимального порога рейтинга, по 30 записей
  с кнопкой «Показать ещё». Исходные ссылки, разбор и статусы общения.
- Статистика за 24 часа / 7 / 30 дней. «Найдено» — прочитанные публикации,
  «Подошло» — уникальные проверенные заказы с подтверждённым бесплатным откликом.
  Сумма временных корзин графика равна числу прочитанных публикаций.
- Генерация отклика через существующий ИИ-клиент по нажатию кнопки с действующим
  лимитом расходов. Повторное нажатие возвращает сохранённый черновик.
  Правки сохраняются в SQLite. Отправки заказчикам нет.
- Пауза плановой проверки каналов после текущей операции; поиск новых источников
  работает независимо. Настройка переживает перезапуск.
- Включение и пауза каналов с существующими правилами курсоров. Новый источник
  сначала проверяется и остаётся кандидатом до отдельного нажатия «Добавить».
  Проверка может использовать ИИ и отправляет обычную карточку владельцу в бот.
- Кнопка «Обновить» запрашивает свежие данные. Автообновления во время правок нет.

## Включение на Маке

В приватном `.env`:

```dotenv
MINIAPP_ENABLED=true
MINIAPP_HOST=127.0.0.1
MINIAPP_PORT=8080
MINIAPP_URL=https://your-public-host.example
```

`MINIAPP_URL` — HTTPS-адрес без пути, query string и fragment. Для локальной
проверки его можно оставить пустым: меню Telegram тогда останется прежним.
Сервер работает в том же `python -m scout.main`, что и существующий бот.
Настройки применяются при перезапуске единственного экземпляра, второй polling
не нужен. Вне Telegram реальный API без подписанного входа недоступен.

Для доступа к Маку из Telegram нужен HTTPS-туннель либо сервер с TLS.
Домен покупать для временной проверки не обязательно. Мак и процесс туннеля
должны оставаться включёнными; смена адреса требует обновления `MINIAPP_URL`
и меню бота. Внешний прокси видит проходящие данные входа и ответы API.
Публикация туннеля настраивается отдельно.

## Развёртывание и защита

HTTP отдаёт только `index.html`, `styles.css`, `app.js`, `live.js`.
База, `.env`, сессия, документация и код Python через него недоступны.
Все API-методы требуют входа владельца. Токен бота и ключи ИИ не передаются
в браузер. API не кешируется, журнал HTTP-запросов выключен, `initData`
не передаются в URL. Демо не обходит защиту API.

В Docker нужно задать `MINIAPP_HOST=0.0.0.0` и отдельно настроить безопасный
reverse proxy. При `network_mode: service:vpn` входящий порт настраивается
у VPN-контейнера. Базовый Compose не публикует API и не меняет схему VPN.
Папка `miniapp` включена в Docker-образ. Для установки Python-пакета вне
репозитория нужно отдельно разместить её рядом с каталогом `scout`.
Git push сам по себе не включает сервер, туннель или авторазвёртывание.

## Проверка

```bash
pytest -q
node --check miniapp/app.js
node --check miniapp/live.js
```

HTTP-тесты используют временную SQLite и тестовую подпись Telegram. Настоящие
сессии, polling, платный ИИ и заказчики в них не задействованы. Реальный WebView,
меню и вход нужно проверить в Telegram после настройки HTTPS-адреса.

[проверка initData](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app),
